## 1. 这份索引回答什么

本文整理下面生成链中真实存在的中间产物、实际内容和注入方式
```text
浏览器/Tracer 原始证据
  → 审核后的 Context Model
  → handbook / workflow Skill / execution contract
  → router 选择注入物
  → Agent prompt
```

必须区分四类文件：

| 层 | 含义 | 常见格式 | 是否直接注入 Agent |
|---|---|---|---|
| Trace / Evidence | 浏览器运行的原始事实 | `.jsonl`、`.json`、`.html`、`.png` | 否 |
| Context Model | 从 Trace 审核、抽象并冻结的网站知识 | 目录化 JSON；历史上也有单文件 `.md` / JSON slice | B 组会直接注入；C/M 组不直接注入完整模型 |
| Generated Skill | 面向某类任务的自然语言工作流 | `SKILL.md` | C/G/H 等 Skill 组直接注入 |
| Machine Contract | 机器可读的路由、动作、选择与成功约束 | `router.json`、`execution-contract.json`、`runtime-contracts/*.json` | M / `baselineB_skill_minimal` 注入 runtime contract JSON |

### 3. Trace 输入证据格式

#### 3.1 原始 Tracer 证据

主要目录：

```text
/Users/rebekah/artifacttrace/local-at/benchmarks/
  context-model-generation/shopping-site/
    platform-core/dev/
      <timestamp>-<capture-or-trace-name>/
```

盘点时该目录有 89 个一级会话目录。不同代际的 Trace 有两种主要布局。

#### A. 分段 JSONL Trace

```text
<trace-session>/
├── trace.meta.jsonl
├── trace.segment.000001.jsonl
├── trace.segment.000002.jsonl
├── ...
├── trace.segments.manifest.json
└── trace.segments.summary.json
```

- `trace.meta.jsonl`：Trace 元信息。
- `trace.segment.*.jsonl`：按事件逐行记录的原始 Trace 分段。
- `trace.segments.manifest.json`：分段清单。
- `trace.segments.summary.json`：分段汇总。

#### B. 页面操作证据包

```text
<workflow-trace>/
├── <name>.metadata.json
├── <name>.interactions.json
├── <name>.network.json
└── <name>.trace.json

<page-capture>/
├── <name>.accessibility.json
├── <name>.html
└── <name>.png
```

- `metadata.json`：会话、页面和采集元数据。
- `interactions.json`：点击、输入、导航等交互。
- `network.json`：请求/响应证据。
- `trace.json`：该工作流的 Trace 汇总。
- `accessibility.json`：可访问性树。
- `html` / `png`：页面结构与视觉证据。

这些文件是证据层，不应直接进入 Agent prompt。

各文件职责：

| 文件 | 内容 |

| `business-core/object-model.json` | 业务对象及字段，例如 product/order |
| `business-core/business-context.json` | 能力成立所需的业务上下文 |
| `business-core/capabilities/*.json` | capability 的输入、输出、对象、业务条件和 provenance |
| `platform-core/surfaces.json` | 页面/Surface 注册表 |
| `actions.json` | 页面支持的动作 |
| `observations.json` | 可观察状态与字段 |
| `state-machine.json` | 页面状态和转换 |
| `evidence-map.json` | 抽象事实到 reviewed Trace 的映射 |
| `platform-core/reviewed/*.jsonl` | 审核后的原始证据索引 |
| `capability-bindings.json` | Business capability 到 Platform surface/action 的绑定 |
| `validation-report.json` | Platform、Business、binding 校验结果 |
| `context-model.freeze.json` | 所有冻结文件及 SHA-256 |

### 7. 从文件看完整链路

```text
独立探索页面 JSON / reviewed JSONL
              │
              ▼
Context Model
  business-core/*.json
  platform-core/**/*.json
  context-model/*.json
              │
              ▼ generate-web-handbook
Generated artifacts
  references/context-model.md
  runtime-skills/<workflow>/SKILL.md
  runtime-contracts/<workflow>.json
  router.json
              │
              ▼ runner 读取 router.runtime_mode
Agent prompt
  Markdown Context Model
  或 Markdown SKILL.md
  或 compact runtime-contract JSON
```

因此，回答“Skill 是什么格式注入 Agent”时必须指向具体实验条件：早期 routed Skill 是
Markdown；Round-53 `baselineB_skill_minimal` 是紧凑 JSON。两者都可能在实验目录中同时存在，
但一次运行只会选择其中一种正文进入 prompt。
